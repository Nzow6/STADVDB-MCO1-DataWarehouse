STADVDB                                        MCO1: Query Processing in a Data Warehouse                           Due Date: October 19-24, 2026 Project Description The course project on Query Processing in a Data Warehouse is a venue for students to integrate their knowledge and skills to achieve the following learning competencies: 1. Build a data warehouse. Design the data warehouse following either the Star or the Snowflake schema, taking into account the dimensional hierarchy needed later for OLAP operations. Table restructuring and denormalization should also be performed as needed. 2. Setup an ETL script to load the data from the source to the warehouse. Perform data wrangling tasks – cleaning, splitting, merging, aggregating, and transforming – when necessary. 3. Develop an OLAP application. Formulate complex and parameterized queries to generate analytical reports that require the use of OLAP operations  – roll-up, drill-down, slice and dice. Design a web-based dashboard interface to display the generated analytical reports. 4. Apply query processing and optimization strategies and evaluate their impact on the performance of the application, specifically, the speed in generating analytical reports from complex SQL queries.  Students will use a public dataset (to be indicated by your teacher) to (1) design a dimensional model for their data warehouse; (2) extract, transform and load the data from this dataset to their model using an ETL script; and (3) formulate queries showing roll-up, drill-down, dice and slice operations. (4) Strategies in improving query processing speed through proper query formulation, the use of indexes, and database restructuring will be evaluated to determine how these affect the response time of the application.  All decisions involved in building the data warehouse (1-2), formulating complex queries that utilize OLAP operations (3), and optimizing query processing speed (4), as well as the method, results and findings from validating that the generated reports are correct (1-3) and evaluating the query performance (4) will be documented in a technical report to be presented as part of the output.    Methodology Students are to form teams with 3 - 4 members who should be under the same instructor. Each team will work on a public dataset (to be indicated by your teacher). To proceed, each team should do the following. Please make sure you abide by the Generative AI usage policies stated in the next section. Step 1. Download and import the dataset to a local MySQL or Postgres Database  Teams must download the source dataset to their local machine and replicate it to their local environment as the SOURCE DATABASE. If necessary, students may increase the size of the source database through synthetic data generation. Step 2. Build the Data Warehouse (AI use: BANNED)  Commented [ECO1]: Dimensional Hierarchy
